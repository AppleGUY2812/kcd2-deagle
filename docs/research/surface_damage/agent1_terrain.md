- terrain_damage.cpp: CTerrain::MakeCrater -> m_StoredModifications.PushModification(pos,r). - TerrainModifications.cpp: PushModification stores {pos,r,height}, calls MakeCrater(mod, n-1): returns if !e_TerrainDeformations; loops units in square r+unit; fDamage = 1 - dist3D/r; depth = clamp(damage - sum earlier-mod depths, 0, TERRAIN_DEFORMATION_MAX_DEPTH=3.f (I3DEngine.h L662)); only if height > waterLevel+0.25; then m_pModifiedTerrain->SetZ(x,y,h); SetHeightMapModified; then ReleaseHeightMapGeometry on intersecting nodes + ResetHeightMapCache. Max real depth ~1 m per blast (damage<=1), stacking limited.
- SerializeTerrainState (savegame): serializes vector of {pos,r,height} "TerrainMods" and REPLAYS MakeCrater on load (C3DEngine::SerializeState L4127 calls it). So persistence = list of explosions, not heightmap.
- RestoreTerrainFromDisk (3dEngineLoad.cpp L1678): if e_TerrainDeformations && !editor -> ResetTerrainVertBuffers + ReloadModifiedHMData from COMPILED_HEIGHT_MAP file.
- **terrain_hmap.cpp L582: `void CTerrain::SetZ(...) { assert(0); //TODO: NOT CURRENTLY SUPPORTED DUE TO NEW INTEGER DATA IMPLEMENTATION }`** => in CE5 mirror the crater is dead code (release: no-op heightmap write; sectors still rebuilt, vegetation removed, decals deleted).
- Heightmap storage: per-sector SHeightMapItem, 12-bit quantised height: ri.fRange=(max-min)/0x0FFF, fOffset=min-TERRAIN_DEFORMATION_MAX_DEPTH ("reserve some space for in-game deformations", terran_edit.cpp) -> design for ~3 m headroom below sector min. Hence SetZ would need re-quantising.
- Physics: CTerrain::InitHeightfieldPhysics (terrain_load.cpp L163) calls IPhysicalWorld::SetHeightfieldData with fpGetHeightCallback = GetHeightFromUnits_Callback (reads live heightmap through an 8-byte-entry cache m_arrCacheHeight); so physics follows heightmap data automatically once ResetHeightMapCache() is called (MakeCrater does).
