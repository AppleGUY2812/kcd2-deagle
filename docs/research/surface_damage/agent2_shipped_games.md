# Shipped games: craters / ground dents (agent2)
VERIFIED (read this session):
- Frostbite (Andersson, SIGGRAPH07 course notes, ch.5 "Terrain Rendering in Frostbite Using Procedural Shader Splatting"): ground destruction updates heightfield pixels; also a destruction MASK (4 px/m, dynamic sparse atlas, crater = small textured decal rendered into mask tiles) swaps materials to burnt dirt; mesh = fixed 33x33 grids so any area can deform at fixed cost; quadtree node min height updated after crater; detail geometry (grass etc.) must be updated. Notes say BF1942-era they lacked memory/perf for arbitrary heightfield destruction.
- BF3 GDC12 (Widmark) slides: heightfield terrain, mesh generated from heightfield, "destruction depth map" (crater depth around static models), "physics material map" (crater depth+width, fx, audio), destruction packed in virtual texture alpha, 4-bit RLE; craters trigger quadtree node updates; 16x16 patches projected-size-constant "support destruction everywhere".
- Cowboy Programming (Mick West): parallax bullet holes: depth in alpha of normal map, UV offset by view dir; no occlusion; steep-angle artifacts; ~35-40 instr. F.E.A.R. = flat quads + depth buffer, early POM impacts (realtimevfx/bgolus).
- Unreal forum 2014: landscape had no runtime modification; decals + normal map suggested. Unity: GetHeights/SetHeights crater stamp (grayscale stamp subtracted) + splat re-weighting.
- SBGames 2024 abstract: craters stored as params in GPU hash table, applied by compute when heightmap block loads (long-distance deformation).
- EA BF6 article: only one-line mention of "terrain deformation" physics; no technique.
- Foxhole devblog 76: trenches = modular resizable structure, collapse to temporary husk; no crater tech given.
NOT confirmed (searches only, snippet-level / hearsay): Arma 3 craters (mod-based, crater objects), Reforger (workshop crater assets, decal FX mod), HLL (anonymous dev-ish reply only), Hunt, Squad, BattleBit, Teardown details, BF1/BFV/2042 specifics, persistence.

## PASS 2 (VERIFIED, read)
- IL-2 Korea dev blog 11 (https://media.il2-korea.com/news/dd_11) + stormbirds summary (https://stormbirds.blog/2024/09/27/il-2-korea-dev-blog-shows-off-new-crater-effects/): crater = 3D crater MODEL tessellated and deformed along the terrain surface to blend edges (mesh stamp + tessellation); goes BELOW ground level (cuts rail/roads); physical collider for vehicles/bullets (rim+interior); only strong explosions; per-mission cap (MP perf); priority keeps airfield craters longest.
- Spintires/MudRunner (https://www.mudrunnermods.com/the-mud-of-mudrunner/, https://80.lv/articles/breakdown-mud-and-water-of-spintires/): 16m blocks; terrain tex 25x25/block (height, mix, tint, mud-replaced alpha), mud tex 128x128/block only where mud (mud height relative to base, offset, track blend); CPU draws wheel primitives into RT, GPU vertex shader displaces; tracks = trapezoid strips, 2-pass with parallax height projected via z-buffer; mud decals = z-projected boxes; physics/render use different datasets ("approximation").
- UT2003 PokeTerrain (https://unrealarchive.org/wikis/unreal-wiki/Legacy:Mod_Ideas/Real_Terrain.html): heightfield-only crater API; problems: pointed bottoms, no tweening, props/decoration floating, craters pile into moats, needs decal for texture, should be much smaller than blast fx.
- Teardown blog index (https://blog.voxagon.se/): index only; spraycan post: 1 byte/voxel palette index; design-notes: ground/rock "unbreakable". No destruction internals.
- DRG (UE spotlight, via search only, fetch 403) mesh-based.
- BF Labs destruction (https://www.ea.com/en-au/games/battlefield/news/battlefield-labs-destruction): persistent surface damage + rubble; nothing on terrain. mp1st BF3 D2.0: buildings only.
